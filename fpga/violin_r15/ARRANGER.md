# 编曲工作台 v1 — 2026-10-23

## 启动

双击本目录 `launch_arranger.cmd`，或运行原 `launch_gui.cmd` 后点击左侧「编曲工作台 · 时间轴」。
沿用现有 Python / tkinter / numpy / pyserial 环境，不安装新框架、不修改 FPGA 或 ESP 固件。
打开页面、创建工程、编辑、保存均不发送板端命令。

## 已实现

- 4/4、480 PPQ 的拍/小节时间轴；30–300 BPM，1–256 小节。
- 最多64条逻辑轨道；吉他、钢琴、Bass、独奏小提琴、12件鼓组；Mute / Solo。
- 双击时间轴空白创建片段；拖动片段移动，拖右边缘改变长度；复制、删除。
- 钢琴卷帘/鼓编号行：双击新增音符、拖动改变时间/音高、拖右边缘改时值、右键删除。
- 精确数值编辑片段起点、长度及音符起点、时值、MIDI音高、力度。
- 1/4、1/8、1/16、1/32吸附及50%–200%水平缩放。
- 轨道力度比例0–127%；不是独立硬件增益插件。
- 播放头定位、循环范围、停止、从当前位置重新播放；离开页面/断连自动停止。
- 22个共享参数的基础设置及时间自动化，包括4条硬件总线、合唱/延迟、吉他/Bass效果链。
- 自动化阶梯/线性插值；线性按约20Hz采样为整数UART参数；开关/类型仅支持阶梯。
- 撤销/重做，版本化 `.tang.json` 工程原子保存/打开，启用轨道音符事件CSV导出。
- 内置8小节「钢琴→吉他→Bass→小提琴 + 鼓」示范；不是商业歌曲录音。
- 串口命令密度、音域、声部、同音重叠、主音色冲突预检查。

## 三分钟上手

1. 先保留默认未勾选的「实机发送」，点击「播放/走带」观察播放头。这是**静音预演**。
2. 选择轨道，双击时间轴的空白位置创建片段，选中片段在下方编辑音符。
3. 片段的起点/长度使用拍数，0起计；卷帘中音符起点相对于片段。
4. 鼓组的音高字段是鼓编号0–11，不是General MIDI鼓音高。
5. 切换「效果器/自动化」，选择参数，双击曲线添加点，拖动移动，右键删除。
6. 基础值在首个自动化点之前生效；拖到曲中播放时，会追踪该位置的参数值。
7. 「起始小节=1、结束边界=5」代表第1–4小节。点击「设循环」后勾选循环。
8. 先「检查实机兼容性」。实机试听需FPGA已准备好、SD参数已加载，并连接顶部FPGA UART串口。
9. 停止原Riff/鼓步进器/曲谱播放器并避免同时拨动传感器；勾选「实机发送」才点击播放。
10. 保存工程使用JSON；CSV只含启用轨道音符，不含效果自动化，不是WAV或MIDI文件。

## 必须说明的硬件边界

当前 v7 `guitar_audio_top.v` 的 `instrument_source_l/r` 是主音色选择器，不是四乐器独立混音：

| 能力 | v1的实际处理 |
| --- | --- |
| 钢琴+鼓同响 | 可发送，钢琴最多16个门控声部 |
| 吉他+鼓同响 | 可发送，吉他32个上下文，实际尾音可能触发声部替换 |
| Bass+鼓同响 | 可发送，Bass最多8个门控声部 |
| 小提琴+鼓同响 | 可发送，小提琴单声部 |
| 钢琴与吉他等不同主音色重叠 | 可编排/静音走带；实机发送前明确拒绝，不快速切音色伪装同时发声 |
| 同乐器多轨 | 合并成该乐器声部；没有每轨独立音频总线 |
| 钢琴/小提琴相同音高重叠 | 实机拒绝，现有协议没有独立音符ID，松音可能影响另一条同音 |
| 吉他/Bass单个音符截止 | 无独立Note Off；矩形时值仅为编排意图，实际自然衰减 |
| 鼓停止与空间效果尾音 | 停止后可能继续自然衰减，不声称立即静音 |
| 效果器位置与数量 | 已有固定硬件链；不能拖出多个独立VST/混响/任意路由 |

钢琴范围MIDI21–108；小提琴55–100；吉他/Bass由现有弦品映射限制。
检查声部数以编排门控区间为准，不等于对实际硬件尾音/频谱的测量。
切换主音色会清理旧声；分段交接可能切断上一段自然尾音。

## 传输与停止行为

- 通过原主窗口FPGA UART口发送现有A5固定6字节控制帧；不是S3 COM30文本协议。
- 主动开始实机播放会设复音模式、停止板端鼓步进器、关闭钢琴踏板、退出手绘音源，并应用本工程共享效果/总线参数。
- 不修改触摸芯片配置，不启用Hall，不自动连接串口，不重刷板卡。
- PC使用单调时钟、绝对事件时间，单向UART无ACK；不声称采样级精确、无抖动或≤5ms。
- 任何事件调度迟到超过150ms时取消未来事件，不把积压音符一次性补发。
- 每100ms命令预算864字节（115200 8N1下保留余量），过密工程拒绝发送。
- 实机停止向所有仍门控中的钢琴/小提琴音符松音，再重选当前主音色清理主声部。
- 循环边界也会清理主声部，然后重新应用参数；不是无缝音频循环。
- 回到曲中播放，保持区间内钢琴/小提琴重新起音；已开始的吉他/Bass/鼓不重新触发。
- 实机效果设置保留在板上，不自动恢复播放之前的状态。已有其他页面的滑杆可能不是板端回读值。
- 串口写入成功不等于FPGA已执行；断连/部分写入时板端状态未知。

## 参考工程与取舍

参考交互设计，不复制其代码、图标、音色或工程文件：

- [LMMS 源码仓库](https://github.com/LMMS/lmms)：Song Editor、Piano Roll、Automation的职责拆分。
- [LMMS 创建轨道说明](https://docs.lmms.io/user-manual/production/creating-a-track)：片段放到时间轴、卷帘编辑音符的工作流。
- [Zrythm 官方功能说明](https://www.zrythm.org/en_GB/features.html)：片段移动/缩放、网格吸附、自动化曲线。

本版是为现有FPGA定制的事件音序器，不是完整商业DAW；不含录音、WAV离线渲染、VST、MIDI导入导出或PC音源。
音频仍由FPGA实时合成，工程保存的是符号音符和控制参数，不是预录PCM。

已新增候选适配：定向四乐器命令、独立Bass音量、带序号/校验的能力探测以及「合奏示例」。

该候选的FPGA综合已通过；完整功能和物理验收以 `../ensemble_daw_v8/tests/results/` 为准，未烧录/未实板听音。

后续实施/验收顺序：

1. 先隔离新FPGA候选，不覆盖已通过物理时序的v7。
2. 将全局音色选择改为带乐器目标的独立事件队列；允许四个引擎保留各自声部，分开使能而不互相清声。
3. 在音频采样边界混合各乐器，重新核算峰值/限幅、DDR带宽及每帧截止时间。
4. 增加乐器总线与效果路由能力描述、序号/ACK、队列余量和时间戳批量事件。
5. 对混合声部、同音重叠、停止/断连、效果切换、最大吞吐做RTL→整机DAC回归，再跑全新综合布局布线。
6. 这些条件通过前，上位机必须保持目前的能力检查，不能仅把冲突检查删掉。
