# V16 Android 蓝牙控制台（LED暂不实施）

基于 V16_FIX1 和 2026-11-01 最新桌面上位机源码；手机通过 ESP32-S3 BLE 和原有 SPI 控制 FPGA。不加数据线，不在手机上替换 FPGA 合成音源。新建的工具、缓存、源码和输出均在 E:/FPGA_Android_20261101。

**本版本需要配套更新 S3 与 FPGA，安装 APK 一项不能让旧 V16 获得完整蓝牙功能。实板联调状态以交付包“验证结果.md”为准。**

## 先安装与烧录

1. 将整个交付目录解压到 E 盘。先保留原 V16_FIX1 压缩包及原可用固件作回退。
2. Android 8.0及以上手机安装 `Android/芯奏界控制台.apk`。这是调试签名的测试安装包，不是应用商店发布包；允许你选择的文件管理器安装。Android 12及以上需要“附近设备”权限；Android 8–11需要蓝牙扫描所需定位权限，部分手机还需开启系统定位服务。
3. FPGA 使用本包经时序检查通过的 `.fs`（若验证结果未通过，则不提供“已验证”位流）。Gowin Programmer中按原板连接与原工程器件设置下载。器件为 GW5AST-LV138FPG676AES；不要把其他板型的位流混用。首次可先下载到 SRAM 验证，断电后会丢失；是否写Flash由实际板卡原有烧录流程决定。
4. S3源码入口：`fpga_spi_work/esp32S3/Guitar_Controller_R15`。CMake依赖同级 `esp32C3/Bluedroid_Connection/main` 的公共触摸源，发给队友时不要只单独发送 S3 文件夹。
5. 在 ESP-IDF 6.1 PowerShell 中进入交付包根目录，运行 `./build_s3.ps1`；或进入上面的 S3 工程后运行 `idf.py -B build_ble build`。沿用 V16 的 ESP32-S3、16MB Flash、Octal PSRAM 配置；如果实际模块不同，先按原硬件配置核对，不能用目标芯片不同的 bin。
6. S3编译成功后，在该S3工程目录运行 `idf.py -B build_ble -p COMx flash monitor`（将COMx换为设备实际串口）。不要执行 erase-flash，以免清掉校准/配对数据。程序、bootloader、分区表的路径和地址均以本次 `build_ble/flasher_args.json` / `flash_args` 为准。未成功编译时不要拿旧 V16 的 bin 当作蓝牙新版烧录。
7. S3上电后在 App 点击“扫描 / 连接BLE”，选择 `FPGA-V16-BLE`，按手机系统提示完成配对。App使用 BLE GATT，不是经典蓝牙SPP；不应在串口终端里寻找一个蓝牙COM口。
8. “霍尔 / 拨弦”页先查询 `FPGA,STATUS` 和 `HALL,STATUS`。FPGA应ONLINE；新SPI能力由每次原始包传输探测。旧位流不支持长包时会拒收/断开，不会假报已加载波表。

## 逐项使用

- **演奏**：吉他6弦×21个原音源品位偏移、Bass低4弦；钢琴MIDI21–108与小提琴55–100；12鼓。钢琴/小提琴使用按下与松开事件，多指可同时按钢琴键；小提琴保留单音逻辑。鼓组计为第5类乐器。
- **力度/模式/踏板**：力度1–127；单音或复音模式；钢琴踏板。上限与现有FPGA声部分配一致，App不凭空增加声部。
- **效果**：沿用11种箱头/失真及6种调制类型的原协议；drive、tone、level、mix、rate、depth、threshold；箱体、噪声门和压缩。参数先编辑再按发送，COMMIT沿用硬件分级更新。
- **混音与空间**：5路总线音量、合唱和延迟。原工程未提供独立混响控制协议，因此本包不将合唱或延迟改名成独立混响。
- **音高表情**：Q20音高比控制吉他滑音与颤音，以20Hz控制更新；这是无线控制率，不是48kHz音频采样率。蓝牙实际触键延迟、抖动与密集事件吞吐须上板测量，不能据RTL仿真直接宣称小于10ms。
- **鼓机**：12鼓×64步，画面分4个16步小节；支持每步力度、BPM、Swing、板端开始/停止。
- **手绘/包络**：绘制1024点周期波形和4096点包络，或输入ADSR生成包络；生成8组抗混叠波表。上传前会退出旧手绘模式、静音并等待，再发送BEGIN、数据、COMMIT和SELECT。上传时不要运行电脑上位机发送、SD播放或进行实体触摸/Hall演奏。队列归零代表SPI传输/重放结束，仍需听音确认硬件是否允许写表并启用；固件目前没有逐个音源语义ACK。
- **编曲编辑**：直接导入/导出 `.tang.json`，五乐器轨道、片段、音符时值/音高/力度、静音/独奏、复制、量化、撤销重做；23项参数自动化支持step/linear。内置最新桌面曲库的32个工程。
- **曲谱回放**：准备阶段先上传包络/参数，全部发送后才启动演奏时钟。按原Tang格式编译成目标乐器命令；同一时间最多合并6条短命令为一个原子包。BLE队列超过80包或调度落后150ms自动停止，避免卡顿后集中补发大量音符。精确硬件节拍仍优先使用板端鼓机；手机曲谱回放依赖手机调度，不是FPGA离线音序器。
- **霍尔**：查询、校准、布防/解除，直接触摸或霍尔触发模式切换；也可在设备页输入原有文本命令。霍尔默认不布防，稳定放置后再校准和开启。
- **节奏练习**：触屏、真实S3触摸事件、Hall拨弦上报，或麦克风起音检测。Perfect/Good/Miss与固定延迟校准；麦克风模式仅判断起音节奏，不作可靠旋律识别。实体输入事件丢失会停止练习，不能靠假事件维持分数。
- **音频观察**：使用手机麦克风显示波形、频谱和左右声道李萨如，显示实际输入采样率；单声道时李萨如为直线。这不是通过BLE传回FPGA数字音频，也不是校准后的THD/SNR仪器。输入流不保存成录音，不改变“声音由FPGA合成”的路径。
- **LED**：按最新要求暂不实施，App无LED入口；S3未初始化RMT灯带，GPIO7/GPIO3不因本次扩展而驱动灯带。之前LED包和原始工程未修改。

## 同时接电脑的边界

保留原PC UART通道。新增SPI只在UART空闲且不存在半个UART包时重放一个完整包；这不是整个多包上传事务的双控制端所有权锁。请始终只用一个控制端上传/播放。不要在手机上传波表时用电脑发送BEGIN/数据/COMMIT；两个端修改同一音源上传状态仍会冲突。普通本机旋钮及物理演奏也应在上传期间暂停。

## 中断与恢复

“停止演奏”会取消手机定时器、待发送队列，发出停止节奏、松踏板、退出合奏等复位指令。BLE断开时S3尝试发送停止命令，但掉电或SPI离线时不能保证声音立即停止。校验错误、旧FPGA、队列过长或超时会中止连接；重新连接后从BEGIN完整重传，不能接着上次半包继续上传。未做断连自动续播。

## 队友最短交接话术

请用ESP-IDF6.1编译本包 `fpga_spi_work/esp32S3/Guitar_Controller_R15`，不要单独拷贝S3目录，公共触摸源在同级esp32C3里。运行 `idf.py -B build_ble build`，将编译日志和整个build_ble内的bin、flash_args、flasher_args.json回传。需要与本包新版FPGA SPI位流配套，旧V16只烧S3不支持完整波表/包络上传。LED这版不做，不要接入LED初始化。烧录后检查触摸/Hall原功能，再连Android的FPGA-V16-BLE，依次测试单音、和弦、鼓、效果、波表、32首曲库中的短曲；不要先擦全片。
